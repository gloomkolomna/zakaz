## 1. Что делаем

VK Mini App **«СобериЗаказ»** — каталог-конструктор заказа изделий для вышивки
(трекеры, наборы, оформление). Покупатель открывает приложение, выбирает товар
и проходит шаги: на каждом шаге — карточки-позиции с фото и ценой, отмечает
нужные, задаёт количество, видит итоговую сумму и отправляет заказ. Заказ
попадает в админку владельца: единый список с фильтрами по товару/разделу/дате
и экспортом в CSV.

Ключевое отличие от «Улицы праздников»: там игра с коллекциями, здесь —
**магазин-конфигуратор**. Общее: стек, VK-авторизация, гейт по подписке,
админка внутри мини-аппа, тесты, деплой.

### Чего в v1 НЕ делаем

Оплата в приложении, расчёт и выбор доставки, воркфлоу статусов (кроме
отмены), уведомления (VK/Telegram/email), корзина из разных товаров, несколько
фото у товара, черновик конфигурации, редактирование отправленного заказа,
отзывы, избранное, поиск по каталогу, промокоды, мультиязычность, PWA/офлайн,
соц-блок.

## 2. Решения (интервью 2026-10-26)

|---|---|---|
| 1 | Модель каталога | **Раздел → Товар → Шаги → Карточки**. Раздел — «подназвание» («Трекер на год», «Трекеры своих хобби»). Шаги и карточки у каждого товара свои |
| 2 | Цена | **Базовой цены нет.** Сумма = Σ (цена карточки × количество). У каждой карточки своя цена в рублях |
| 3 | Количество | **Своё у каждой позиции** (степпер «− 1 +»), ограничение `max_qty` у карточки |
| 4 | Выбор в шаге | **Настраивается у шага**: «один из N» или «можно несколько». Шаг можно пропустить (0 отмеченных) |
| 5 | Обязательные шаги | Флаг `is_required` у шага; по умолчанию все пропускаемые. «Отправить» активна, если отмечена ≥1 карточка |
| 6 | Варианты в шаге | От 1 до N карточек (N не ограничено, типично 2–5); добавляются/редактируются в админке |
| 7 | Корзина | **Один товар = один заказ.** Разные товары в одном заказе не смешиваются |
| 8 | Цена в каталоге | На карточке товара — **«от N ₽»** = сумма самых дешёвых карточек по всем шагам товара |
| 9 | Фото | По **1 фото** у товара и у карточки, тап — просмотр на весь экран (портал, z-100) |
| 10 | Данные покупателя | **Ничего не спрашиваем** — только VK-профиль (vk_id, имя). Связь и доставка — в ЛС ВК |
| 11 | Оплата | **Нет** оплаты в приложении: заявка → владельцу, дальше переписка |
| 12 | Аудитория | **Только подписчики сообщества** (VK API `groups.isMember`, кэш), админ — мимо гейта |
| 13 | После отправки | Экран подтверждения с номером заказа; заказ появляется в «Моих заказах» |
| 14 | Заказы в админке | Список + фильтры (товар/раздел/даты/статус) + поиск + карточка заказа + **бейдж «новые»** (флаг `read_at`) + **экспорт CSV** |
| 15 | Статусы заказа | **Три**: «в работе» (`new`), «выполнен» (`done`), «отменён» (`cancelled`). Воркфлоу с отправкой/оплатой в v1 нет |
| 16 | Уведомления | **Только админка + бейдж.** Никаких VK-сообщений, Telegram, email |
| 17 | Дизайн | **Вариант A «Красная нить»** выбран 2026-10-26; фирменные цвета/лого — этап 4 |
| 18 | Деплой | Тот же сервер/домен, префикс **`/zakaz/`**, API **:8006**, новое VK-приложение, новый git-репозиторий |
| 19 | Группа и админы | Гейт — сообщество **206593200**; админы **400977**, **795384** (как в «Улице праздников») |
| 20 | Название | Рабочее **«СобериЗаказ»**; финальное имя — вместе с брендингом |
| 21 | Мои заказы | Покупатель видит **свои заказы**: список (номер, товар, дата, позиции, сумма, статус) и детали состава |
| 22 | Отмена заказа | Покупатель может **отменить** заказ; владельцу в админке загорается **красная плашка** «Отмена заказа №N», пока он не нажмёт «Понятно» |
| 23 | Редактирование | На «Ваш заказ» **до отправки**: количество (степпер), убрать позицию, **перевыбор шага** — «Изменить» открывает шторку с вариантами шага, выбор применяется сразу, «Готово» закрывает |
| 24 | После отмены | Состав сохраняется в истории; кнопки отмены нет; предлагается написать в сообщество |

## 3. Допущения (прямые следствия решений — возразите, поменяем)

1. **Цены — целые рубли**, хранятся `INTEGER` (копейки не нужны). Формат
   вывода: `1 250 ₽` (неразрывный пробел, `ru-RU`).
2. **Количество**: минимум 1, максимум `max_qty` карточки (по умолчанию 10,
   админ меняет 1–99). Ноль = «не выбрано».
3. **Снятие выбора**: повторный тап по выбранной карточке снимает выбор
   (в режиме «один из N» — переключает на другую).
4. **После отправки состав неизменяем**: правка = отменить заказ и собрать
   новый. Редактирование — только на «Ваш заказ» до отправки.
5. **Снапшоты**: в заказе сохраняются название шага, название карточки, цена,
   количество и имя покупателя на момент заказа; правки каталога не
   переписывают историю.
6. **Удаление** разделов/товаров/шагов/карточек — мягкое (`is_active=0`),
   если на них есть ссылки в заказах; жёсткое — только для «чистых» записей.
7. **Пустой каталог** — экран «Скоро здесь появятся товары»; товар без шагов
   в каталоге помечается «скоро» и недоступен для сборки.
8. **Заказ без единой позиции запрещён** — 400, кнопка «Отправить» неактивна.
9. **Тексты** «Доставка», «Оплата», «Контакты», «Политика ПД» — редактируются
   в админке (plain text с переносами), отдаются публично.
10. **Фото товаров/карточек** — локально в `api/uploads/`, при `S3_ENABLED=1` —
    в тот же бакет `korgiholidays`, префикс `zakaz/` (по конвенции референса).
11. **Порты**: dev-фронт 5177, dev-API 8006, прод-API 8006 (8004/8005 заняты).
12. **Один активный товар-конструктор за раз** у покупателя в рамках вкладки;
    переход в другой товар — новый заказ (старый не сохраняется).
13. **Никаких писем/пушей покупателю** — экран подтверждения и «Мои заказы».
14. **Отменить можно любой заказ, пока он не отменён.** Ограничения «уже
    отправлен» нет: если посылка в пути, владелец решит в переписке. При
    желании добавим статус «принят», после которого отмена недоступна.
15. **Отмена не удаляет заказ**: статус `cancelled`, состав и сумма остаются
    в истории покупателя и в админке.
16. **Плашка отмены** в админке горит до нажатия «Понятно» (флаг
    `cancel_seen_at`); на покупателя это не влияет.
17. **Очередь** — заказы со статусом `new`, упорядоченные по `queue_order`
    (растёт, при равенстве — по `created_at`). Новый заказ получает
    `max(queue_order) + 1`, то есть в конец. Позиция **не хранится отдельно**:
    это индекс в этом порядке + 1; отменённые и выполненные в очередь не
    входят.
18. **«Выполнить»** — `new` → `done` (`done_at`): заказ уходит из очереди,
    позиции остальных сжимаются.
19. **Ручной порядок**: стрелки ↑/↓ меняют `queue_order` с соседним активным
    заказом (в одной транзакции); на краях кнопки неактивны. Позиции
    покупателей пересчитываются сразу. Drag-and-drop — возможное расширение,
    в v1 стрелки.
20. **Отмена** доступна только для `new`: выполненный заказ отменить нельзя
    (кнопки нет, API → 409).

## 5. Пользовательские сценарии

### Покупатель

1. Открывает мини-апп из сообщества → VK Bridge отдаёт `vk_user_id` →
   `POST /auth/session` (проверка подписи + подписки) → JWT.
2. Не подписан → экран «Подпишитесь на сообщество» + кнопка «Я подписался»
   (перепроверка).
3. Каталог: разделы, внутри — карточки товаров (обложка, название, «от N ₽»).
4. Тап по товару → экран товара: обложка (зум), описание, «Собрать заказ».
5. Конфигуратор: шаги по одному, стрелки ←/→ и «Далее», прогресс «Шаг 2 из 4»,
   название шага, карточки сеткой 2 в ряд (напротив друг друга), у каждой —
   фото, название, цена, чекбокс/радио, степпер количества при выборе;
   «Пропустить шаг» (если не обязательный).
6. Последний шаг → «Ваш заказ»: состав по шагам, **редактирование** (количество,
   убрать, перейти к шагу), сумма, «Отправить заказ».
7. Успех: «Заказ №15 отправлен» + сумма + кнопки «Мои заказы» / «В каталог».
8. «Мои заказы»: список своих заказов со статусом, **позицией в очереди** и
   суммой → детали состава → **«Отменить заказ»** с подтверждением.
9. Позиция в очереди видна и на экране успеха после отправки.

### Админ (владелец)

1. Вход тем же путём; роль `admin` по `ADMIN_VK_IDS`; гейт подписки не применяется.
2. «Управление» → разделы: создать/переименовать/скрыть/порядок.
3. Товары: создать в разделе, загрузить обложку, описание, порядок, скрыть.
4. Экран товара: шаги (название, режим выбора, обязательность, порядок,
   скрыть) → внутри шага карточки (название, цена, лимит количества, фото,
   порядок, скрыть).
5. Заказы: **очередь** — список пронумерован (1, 2, 3…) по времени, у каждой
   строки кнопка «Выполнить»; горящая плашка отмены сверху — «Отмена заказа №N»
   с кнопкой «Понятно», горит до подтверждения. Фильтры, поиск, карточка
   заказа, «прочитан», экспорт CSV.
6. Тексты: доставка/оплата/контакты/политика ПД.
7. Логи: 4xx/5xx и ошибки.

## 6. Схема БД

SQLite (WAL, `foreign_keys=ON`), SQLAlchemy 2.x, Alembic. Все даты — UTC
(`datetime.utcnow`), «дни» для фильтров — МСК (`services/msk_time.py`).

### users
| Поле | Тип | Примечание |
|---|---|---|
| vk_id | Integer PK | |
| role | String | `player` / `admin` |
| status | String | `active` / `blocked` |
| display_name | String | из VK API `users.get` |
| is_member | Boolean | кэш подписки |
| member_cached_at | DateTime | кэш 24 ч |
| created_at | DateTime | |

### sections
`id` PK · `title` String · `sort_order` Int · `is_active` Bool · `created_at`

### products
`id` PK · `section_id` FK → sections (CASCADE) · `title` String ·
`description` Text · `image_url` String · `sort_order` Int ·
`is_active` Bool · `created_at`
Индекс: `(section_id, sort_order)`.

### product_steps
`id` PK · `product_id` FK → products (CASCADE) · `title` String ·
`hint` Text NULL · `selection_mode` String (`single`/`multi`) ·
`is_required` Bool · `sort_order` Int · `is_active` Bool · `created_at`
Индекс: `(product_id, sort_order)`.

### step_cards
`id` PK · `step_id` FK → product_steps (CASCADE) · `title` String ·
`description` Text NULL · `image_url` String · `price` Int (рубли) ·
`max_qty` Int (default 10) · `sort_order` Int · `is_active` Bool · `created_at`
Индекс: `(step_id, sort_order)`.

### orders
`id` PK · `user_id` FK → users.vk_id (CASCADE) · `buyer_name` String
(снапшот) · `product_id` FK → products (SET NULL, nullable) ·
`product_title` String (снапшот) · `section_title` String (снапшот) ·
`total` Int (рубли) · `items_count` Int ·
`status` String (`new` / `done` / `cancelled`, default `new`) ·
`queue_order` Int (nullable; порядок в очереди, вручную) ·
`created_at` DateTime (index) · `read_at` DateTime NULL ·
`cancelled_at` DateTime NULL · `cancel_seen_at` DateTime NULL ·
`done_at` DateTime NULL
Индексы: `created_at`, `(status, queue_order)`, `(status, cancel_seen_at)`,
`(user_id, created_at)`.
Позиция в очереди — индекс в порядке `(queue_order, created_at) + 1`; новый
заказ получает `max(queue_order) + 1`; стрелки меняют `queue_order` с соседом.

### order_items
`id` PK · `order_id` FK → orders (CASCADE) · `card_id` FK → step_cards
(SET NULL, nullable) · `step_title` String · `card_title` String ·
`image_url` String · `price` Int · `qty` Int · `sum` Int
Индекс: `order_id`.

### settings
`key` PK · `value` Text — тексты (`text.delivery`, `text.payment`,
`text.contacts`, `text.privacy`), служебные флаги.

### logs
Как в референсе: `id`, `source`, `level`, `event`, `method`, `path`,
`status_code`, `message`, `details`, `user_id`, `client_ip`, `created_at`.

**Правила**: миграция на каждое изменение `models.py`
(`alembic revision --autogenerate` + `upgrade head`); БД не пересоздаётся.

## 7. API

Префикс `/api`, JWT `Authorization: Bearer`, все ответы JSON.
Ошибки: `{"detail": "..."}` или `{"detail": {"code": "...", "message": "..."}}`.

### Авторизация и профиль
| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| POST | `/auth/session` | публично | VK-подпись → JWT; гейт подписки; создание пользователя; роль admin по env |
| GET | `/me` | JWT | `{vk_id, display_name, role}` |

### Каталог (покупатель)
| Метод | Путь | Назначение |
|---|---|---|
| GET | `/catalog` | Разделы с товарами: `{sections:[{id,title,products:[{id,title,image_url,from_price,steps_count}]}]}` |
| GET | `/products/{id}` | Товар + шаги + карточки (только активные, только заполненные): `{id,title,description,image_url,from_price,steps:[{id,title,hint,mode,is_required,cards:[{id,title,description,image_url,price,max_qty}]}]}` |
| GET | `/info` | `{delivery, payment, contacts, privacy}` |

`from_price` = Σ минимальных цен по шагам (только активные карточки);
если карточек нет — `null` (UI: «скоро»).

### Заказы (покупатель)
| Метод | Путь | Тело/ответ |
|---|---|---|
| POST | `/orders` | `{product_id, items:[{card_id, qty}]}` → `{id,total,created_at,queue_position,items:[...]}` |
| GET | `/me/orders` | Свои заказы: `{items:[{id,total,status,created_at,cancelled_at,product_title,items_count,queue_position}]}` |
| GET | `/orders/{id}` | Свой заказ (или админ): состав, сумма, статус, `queue_position` |
| POST | `/orders/{id}/cancel` | Свой заказ, статус `new` → `cancelled`; 409 если уже отменён/выполнен; ответ — заказ |

**Валидации POST /orders** (все → 400 с понятным текстом):
товар существует и активен; `items` 1..100; карточки существуют, активны,
принадлежат шагам этого товара; нет дублей `card_id`; `1 ≤ qty ≤ max_qty`;
в шаге `single` — не более одной карточки; каждый `is_required` шаг имеет
≥1 карточку. Сумма считается **на сервере** из БД, клиентская игнорируется.
Создание заказа и позиций — одна транзакция.

**Отмена**: только владелец заказа; `status='cancelled'`, `cancelled_at=now()`,
`cancel_seen_at=NULL`; повторная отмена — 409; чужая — 403; выполненный — 409.
Состав и сумма не меняются, заказ остаётся в истории и в админке.

**Очередь**: `queue_position` = индекс заказа в списке `new`, упорядоченном
по `queue_order, created_at`, плюс 1. `null` для отменённых и выполненных.
Считается одним запросом на список, не N+1.

**Ручной порядок**: `POST /admin/orders/{id}/move {direction: "up"|"down"}`
меняет `queue_order` с соседним активным заказом (409, если соседа нет или
заказ не `new`). Новый заказ — в конец очереди.

| POST/DELETE | `/admin/cards/{id}/image` | загрузка/сброс фото |
| POST | `/admin/cards/reorder` | `{step_id, ids:[...]}` |
| GET | `/admin/orders` | фильтры `section_id, product_id, date_from, date_to, q, unread, status (new/done/cancelled), queue (1 = только очередь), cancel_unread, limit, offset`; ответ `{items, total, summary:{count, queue, unread, sum, cancelled, cancelled_unread}}`; у каждого элемента `queue_position` |
| GET | `/admin/orders/{id}` | деталь: позиции, покупатель, сумма, статус, `queue_position`, отмена |
| POST | `/admin/orders/{id}/read` | отметить прочитанным |
| POST | `/admin/orders/{id}/complete` | `new` → `done`, `done_at=now()`; 409 если уже не new |
| POST | `/admin/orders/{id}/move` | `{direction: "up"\|"down"}` — меняет порядок с соседом; 409 на краю/не `new` |
| POST | `/admin/orders/{id}/cancel-seen` | подтвердить, что отмена увидена (гасит плашку) |
| GET | `/admin/orders/export.csv` | те же фильтры, CSV UTF-8 BOM, `;`, колонка «Очередь» |
| GET/PUT | `/admin/texts` | тексты страницы «Информация» |
| GET | `/admin/logs?level=&limit=` | логи |

Все `/admin/*` — `require_role("admin")`, иначе 403.

### Загрузки
`POST /api/uploads` не нужен: файл идёт в `POST /admin/.../image`
(multipart). Валидация: ≤ 10 МБ, `image/*`, HEIC поддержан (`pillow-heif`),
сжатие до 1400 px по длинной стороне, JPEG q85; ответ `{url}`.
Статика: `/api/uploads/<file>`.

### Конфигуратор — поведение
- Состояние выбора живёт в `useState` внутри `Product.tsx`
  (`selected: Record<cardId, qty>`), шаг — в query-параметре → работает
  «назад» браузера и VK.
- Переход вперёд: если шаг обязательный и пуст — кнопка неактивна + подсказка.
- «Пропустить шаг» очищает выбор этого шага и ведёт дальше.
- Итоговая сумма считается на клиенте для показа и **пересчитывается сервером**
  при отправке; расхождение не критично (сервер — истина).
- Индикатор: «Шаг N из M» + точки; в шапке — текущая сумма (опционально,
  только если > 0).

### Состояния и ошибки
Скелетоны при загрузке; пустые состояния («Скоро», «Ничего не выбрано»);
ошибка сети — «Повторить»; 403 `members_only` — экран подписки; 401 —
авторелогин (интерцептор); 404 — «Товар недоступен»; 400 — тост с текстом.

### Адаптивность и VK-iframe (обязательно)

VK открывает мини-приложение в iframe: на десктопе **630×600 … 1000×4050 px**
(размер задаёт VK), на мобильном — webview 360–430 px. Поэтому:

- **Три диапазона.** ≤ 619 — телефон: одна колонка, поля 20. 620–879 —
  компактный десктоп: каталог в 2 колонки, в шаге 3 карточки, поля 28.
  ≥ 880 — десктоп: каталог в 3 колонки, товар «фото слева + текст справа»,
  заказы в 2 колонки, оболочка до 1000 px.
- **Никакой горизонтальной прокрутки** на 360, 630 и 1000: `min-width: 0`
  у грид-детей, `max-width: 100%` у медиа, длинные названия переносятся.
- **Высота 600** (минимум iframe): первый экран показывает заголовок и начало
  контента, нижняя панель 72 px липнет к низу, шторки — `max-height: 88dvh`
  с внутренней прокруткой и закреплённым действием.
- **Товар на десктопе:** фото 4:5 в левой колонке (не выше 560 px), справа —
  название, цена, описание, характеристики; на телефоне — одна колонка.
- **Заказ на десктопе:** контент 780 px по центру; кнопка отправки в липкой
  панели по центру, не на всю ширину.
- **Админка:** до 900 px, чтобы сумма не улетала от названия; очередь и
  стрелки остаются в одной строке.
- **Тап-цели** ≥ 44 px на всех ширинах; hover — только при
  `(hover: hover) and (pointer: fine)`.
- **Проверка перед сдачей:** 360×640, 390×844, 430×932, **630×600**,
  768×700, **1000×700**, 1000×4050. Скриншоты + `scrollWidth = innerWidth`.

2. Гейт: не подписан → 403 `members_only`; подписан → 200; кэш 24 ч;

3. Каталог: только активные, порядок сортировки, `from_price`, пустой каталог.
4. Админ-CRUD: happy, права (player → 403), 404, валидации, мягкое удаление,

5. Заказы: happy, пустой, дубли, чужая карточка, qty границы, single-режим,
   обязательный шаг, сумма, снапшоты, цена из БД, транзакционность,
   чужой заказ → 403, несуществующий → 404.
6. Мои заказы: только свои (чужие не попадают), порядок по дате, статус,
   `queue_position` (1..N по new), пустой список.
7. Очередь: порядок по `queue_order`; новый заказ — в конец; `null` у
   отменённых/выполненных; после «Выполнить» и после отмены позиции
   сжимаются; стрелки меняют порядок с соседом и пересчитывают позиции;
   на краю — 409, чужой/не new — 409.
8. Отмена: своя → `cancelled` + `cancelled_at`; чужая → 403; повторная → 409;
   выполненная → 409; состав и сумма не меняются; в списке «Отменён».
9. «Выполнить»: `new` → `done` + `done_at`; повторное → 409; заказ уходит из
   очереди; в списке покупателя «Выполнен».
10. Админ-заказы: фильтры (в т.ч. `status`, `queue`, `cancel_unread`), поиск,
    пагинация, summary (включая `queue`, `cancelled`, `cancelled_unread`),
    «прочитан», `cancel-seen` гасит плашку, CSV с колонками «Очередь»/«Статус»,
    права.
11. Тексты: чтение публично, запись только админ.
12. Логи: middleware пишет 4xx/5xx.

**Фронтенд (vitest + jsdom):** формат цены и расчёт суммы; логика выбора
(один/несколько, снятие, обязательность); редактирование легенды (qty,
удаление, пустое состояние); **перевыбор шага шторкой** (замена варианта,

отмена (диалог → статус); позиция в очереди в карточке/деталях;
401-авторелогин; пустые состояния.

**Ручные проверки:** мобильный VK (iOS/Android), длинные названия, 5 карточек
в шаге, количество 10, зумы, «назад» браузера, медленная сеть.

## 13. Безопасность и персональные данные

- Храним минимум: `vk_id`, имя, заказы. Телефон/адрес не собираем.
- JWT подписывается `SECRET_KEY`, срок 180 дней (как в референсе), 401 →
  авторелогин.
- Подпись VK проверяется HMAC-SHA256 по `VK_APP_SECRET`; дев-обход только
  при `APP_ENV=dev`.
- Загрузки: проверка MIME/размера, пережатие, уникальные имена.
- Политика ПД — текст в админке + ссылка на странице «Информация».
- Админ-эндпоинты закрыты ролью; чужие заказы недоступны.

## 14. Риски и меры

| Риск | Мера |
|---|---|
| Гейт подписки зависит от VK API | кэш 24 ч, fail-open для уже вошедших, лог ошибок |
| Расхождение цены клиент/сервер | сумма только на сервере, снапшоты в заказе |
| Путаница «товар без цены» | «от N ₽» в каталоге + явный итог на каждом шаге |
| Потеря заказа при сбое | транзакция, лог, повторная отправка |
| Долгое наполнение каталога | админка с копированием шагов/карточек (этап 4, если попросите) |
| VK WebView-особенности | мобильный первый, тесты на живом VK, портал для модалок |
| Брендинг задерживает запуск | этап 4 изолирован: до материалов — нейтральная тема |
| Спам-заказы | лимит частоты на `POST /orders` (например, 10/мин на пользователя) |
| Отмена уже отправленного заказа | владелец решает в переписке; при необходимости — статус «принят» (открытый вопрос) |

## 16. Порядок, зависимости, оценка

```
0 → 1 → 2 → 3 → 4 → 5
```

- 0–2 — ядро (без него нет заказа).
- 3 — админка заказов и очередь (можно параллельно с 4, но после 2).
- 4 — брендинг (нужны материалы; можно частично параллельно).
